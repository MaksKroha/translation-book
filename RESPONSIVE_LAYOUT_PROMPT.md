# Responsive layout: make every page look right on phones, tablets and laptops

You are the expert responsible for the responsive ("adaptive") layout of my website. Every page must
display correctly on every common screen: small and large phones (portrait and landscape), tablets,
laptops and wide desktop monitors. That means nothing cut off, no sideways scrolling, sensible line
lengths, consistent alignment and spacing, readable text, and buttons and links that are easy to tap.

**Find the problems, fix them, and prove the fixes with before/after screenshots.** Don't commit, push
or deploy. I'll review the diff and push myself.

I'm not a web developer. Explain what you found and changed in plain language.

## Screens to test

At minimum, these viewport widths (CSS pixels):

- **Phones, portrait:** 320 (smallest still in use), 360, 375, 390, 412, 430
- **Phones, landscape:** 667×375 and 844×390
- **Tablets:** 768 (portrait) and 1024 (landscape)
- **Laptops and desktops:** 1280, 1366, 1440, 1920
- **Breakpoint edges:** 479/480, 639/640, 759/760 px, where a layout switches

Run each in **light and dark** theme. Also check larger text: browser zoom at 200%, and the phone's
"large text" setting (simulate it with a larger root font size).

## What "correct" means

- **No horizontal scrolling at any width.** Check it with
  `document.documentElement.scrollWidth <= document.documentElement.clientWidth`, not just by eye.
- **Nothing cut off or overflowing.** Watch for long unbroken strings:
  - the contact email in the footer and on legal pages (`vladyslavzariskyi@gmail.com` is long at 320 px)
  - long Ukrainian words in headings, long book titles, and the site address in the public offer's text
  - the 6-digit code box on `/pay/` (it uses `2rem` with letter spacing)
- **Cloudflare Turnstile widget.** It sits on the book page and the request form. It's normally
  invisible (`data-appearance="interaction-only"`), but when Cloudflare wants the visitor to tick a box
  it shows a box of fixed width. Check its current sizes (`normal`, `flexible`, `compact`) in Cloudflare's
  Turnstile docs. Make sure it can't push the page wider than a 320 px screen, and that it doesn't jump
  the layout when it appears.
- **Alignment and spacing are consistent.**
  - Content edges line up with the header and footer (`.wrap`).
  - Vertical rhythm between sections is even.
  - Centred vs left-aligned sections look intentional, e.g. the centred hero above a grid that holds
    only one book on desktop.
  - The Buy buttons in the price row and at the bottom stretch on phones and look right on desktop.
- **Readable.** Body text never below about 16 px. Line length around 45–80 characters on wide screens.
  Headings scale smoothly (`clamp()` is used already). Good contrast in both themes.
- **Easy to tap.** Buttons and links are at least about 44×44 px, with enough space between neighbours.
  Watch the footer links when they wrap. Form fields never trigger iOS zoom-on-focus, which needs a
  font size of at least 16 px.
- **Images.**
  - Covers keep their proportions and don't stretch.
  - There's no layout jump while they load: `width`/`height` attributes are already set, so keep them.
  - `srcset`/`sizes` still pick a sensible file at each width.
- **Forms** (the request form): labels, hints, fields, the button and the notes under the form line up
  at every width. Error pages with a list look tidy.
- **Landscape phones:** the header and content still fit, and nothing is hidden behind fixed elements.
- **Motion:** respect `prefers-reduced-motion` (the cover hover lift on the home page).
- Keyboard focus stays visible on every interactive element.

## Rules

- **Keep the look.** Fix layout and spacing; don't redesign. Keep the colours, fonts, wording and page
  structure. If something needs a bigger change (a new layout for a section), describe it and ask me
  first instead of doing it.
- **Change as little as possible.** Most fixes belong in `assets/style.css`. Change HTML in `build.py`,
  `lib/html.js` or `functions/pay/index.js` only when CSS alone can't do it, and keep the existing class
  names working.
- **No inline styles and no new inline scripts.** The security review notes that the static pages have
  none, so a strict Content-Security-Policy stays possible. Use classes in `style.css`.
- **No new dependencies:** no frameworks, no npm or pip packages, no `package.json`, no web fonts.
- **Don't touch payment or form logic:**
  - `lib/jar.js`, `lib/requests.js`, `lib/guard.js`
  - the webhook, `/download`, and the `/buy` and `/api/translation-request` handlers
  - on `/pay/`, the markup and CSS only; leave the script's behaviour alone
- **Don't hurt SEO.** Keep headings, `<title>`, meta tags, canonical links, JSON-LD and the alt texts.
- **Copy style**, if you must touch any visible text: Ukrainian only, «» quotes, the ’ apostrophe.
- Keep screenshots, test pages and helper scripts **outside the repo** (a temporary directory).

## How to work

1. **Build and serve the static pages:**
   ```bash
   python3 build.py
   python3 -m http.server -d public 8000
   ```
2. **Render the Worker pages into files** so they can be screenshotted:
   - Node isn't installed. Download the official Node binary into a temporary directory and check its
     SHA256 against `SHASUMS256.txt` from nodejs.org.
   - Write a small script (outside the repo) that imports the real `lib/html.js` and
     `functions/pay/index.js`. For `/pay/`, use a fake `env.DB` built on `node:sqlite` holding a pending,
     an underpaid and a paid order, and mock `fetch` so nothing reaches monobank.
   - Save each page's HTML into a **temporary copy** of `public/`, so `/style.css` and `/favicon.svg` load.
   - Remove the `<script>` from the saved `/pay/` copies only. Otherwise its status check fails against
     the static server and reloads the page in a loop.
3. **Screenshots.** Google Chrome (`/usr/bin/google-chrome`) and Firefox are installed.
   - **Quick look:** `google-chrome --headless=new --window-size=390,1600 --screenshot=out.png <url>`
     (use a tall window to capture the whole page). Force the light theme with
     `--blink-settings=preferredColorScheme=1`; `0` is dark.
   - **Proper phone emulation and measurements:** a plain window size doesn't emulate a phone (touch,
     device pixel ratio, `hover` media queries). For that:
     1. Start Chrome with `--remote-debugging-port`.
     2. Drive it from a Node script using Node's built-in `WebSocket` and the DevTools protocol:
        `Emulation.setDeviceMetricsOverride` (with `mobile: true`) and `Emulation.setTouchEmulationEnabled`
        to emulate the phone; `Runtime.evaluate` to measure overflow; `Page.captureScreenshot` with
        `captureBeyondViewport` to capture.
     3. For each page and width, run a script that lists any element wider than the viewport.
4. **Stress content.** Copy the repo to a temporary directory, then:
   - add a second and third book to `catalog.json` with very long titles, subtitles and author names
   - add a FAQ item with a long word, and a long link in the legal text

   Build it there and check the grid, the book page and the cards. Never put test data in the real
   `catalog.json`.
5. **Fix, then repeat** steps 1–4 until every page passes at every width in both themes.
6. Run `python3 build.py` in the real repo one last time and make sure it prints no new warnings.
